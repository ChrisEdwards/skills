# Goat Triage Batch

Batch-triage a scoped set of open Beads using a `/goal` style objective. Each triaged bead gets a root-cause comment and labels. To turn one triaged bead into a reviewed implementation plan, use goat-triage.

## Invocation

The text after the skill invocation is the bead scope. If the scope is missing, ask for it. If the scope is present, start a goal with the objective below, substituting `{scope}` with the user's scope text.

If the `create_goal` tool is available, use it. If the current surface does not expose goal tooling, continue manually using the same objective.

## Goal Objective

```text
Triage the following scope of beads: {scope}.

Resolve the scope to concrete candidate bead IDs before making changes. The scope may include explicit bead IDs, parent beads whose children should be triaged recursively, label/status filters, or a natural-language Beads query.

Only triage beads whose current status is `open`. Skip closed, deferred, in-progress, and any other non-open beads before checking triage labels, investigating root cause, commenting, or adding labels.

Skip any bead that has already been triaged. A bead has already been triaged if it has the `triaged` label or any current triage-state label defined in the repo's triage mapping file, including `needs-decision`, `needs-info`, `ready-for-agent`, `ready-for-human`, or `wontfix`. Treat existing `needs-triage` labels as legacy equivalents of `needs-decision` when reading old beads.

For each remaining candidate bead, determine whether it is still applicable and determine the true root cause. If you need to trace the behavior through code, APIs, data sources, or backend services, do so. If the relevant codebase is not cloned nearby, use available repo tooling such as `gh` to inspect or obtain the code when appropriate.

Once you have the true root cause, generate three plausible solutions, compare them, and choose the best one. Add a comment to the bead with your analysis, the chosen option, and enough context for both a human reviewer and an implementation agent to understand the issue and make the fix.

Every triage comment must start with:

> *This was generated by AI during triage.*

Use this comment structure:

## Root Cause

State whether the bead is still applicable, then explain the true root cause.

## Options Considered

* Option 1: ...
* Option 2: ...
* Option 3: ...

## Recommended Option

Name the selected option and justify why it is the best tradeoff.

## Agent Implementation Notes

* ...

After commenting, add the `triaged` label. Also add one or more `repo:*` labels indicating where code changes are needed, for example `repo:web-app` or `repo:api-service`. If multiple repositories are impacted, add a label for each. If the repository is unknown, add `repo:unknown`.

If the bead is ready for autonomous implementation, add `ready-for-agent`. If it requires human implementation, add `ready-for-human`. If it is waiting on more reporter information, add `needs-info`. If maintainer deliberation is still needed before it can become actionable, add `needs-decision`, not `needs-triage`.

Continue until all open, untriaged candidate beads in the resolved scope have been triaged, commented on, and labeled appropriately. Run `br sync --flush-only` after bead edits.
```
